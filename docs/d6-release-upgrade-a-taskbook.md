## 一、本轮目的：把产物预检推进到真实安装和数据保留证据

上一批证明了“旧包与新包身份正确、资源一致，云端临时模拟器具备隔离实验条件”，但没有安装原始 release 145，也没有在实际 release 数据目录中验证学习记录。

本轮解决三个问题：

1. 原始 release 0.3.145 能否在新建测试环境中通过真实键盘完成离线输入，并形成可重复的学习数据基线？
2. 0.3.145 不卸载、不清数据覆盖为 0.3.149 后，安装前的数据以及首次启动后的逻辑学习记录是否保留？
3. 怎样在不往正式 APK 添加探针、不读取运行中数据库、不让观察器替原应用学习或落盘的前提下，得到可信证据？

本轮完成后，最多可宣布：**API 36 / x86_64 云端隔离环境中的原始 release 基线及同资源版本 A 升级通过**。不能宣布 D6 完成、真实词典迁移完成、所有强杀或 OEM 服务重建通过。

## 三、范围、重点与明确不做项

### 3.1 本轮要做

1. 独立测试应用：自有简单输入框、自进程 instrumentation 与 UIAutomator，通过正式 IME 的真实按键/候选完成输入。
2. 独立冷态副本观察器：仅在测试/debug 设施中运行，读取专用人工数据副本，输出固定词条计数和 reading 检查结果。
3. 145 首次安装、离线英文/中文输入、人工词负对照、学习及旧包冷启动基线。
4. 唯一真实升级链：原始145 → 原始149，同资源版本、不卸载不清数据。
5. 用户学习记录、人工 sentinel、无副作用配置以及最近符号的保留验证。
6. 两套独立全新模拟器中的完整重复，脱敏报告和相关既有回归。

### 3.2 核心重点

- **真实 release**，不是给 debug APK 加相同包名；正式APK字节不可变。
- **真实输入链**，不是给编辑框 setText 或用 adb input text 冒充键盘输入。
- **真实学习记录**，不是只看到候选、排名上升或合成句出现。
- **观察不污染来源**：原应用先退出，副本后观察；不通过探针 flush 来源数据库。
- **先基线、后升级**：旧版记录不能持久化时，A 链只能阻塞，不能继续凑安装成功证据。
- **结果有边界**：固定冷进程边界不是全部崩溃场景，模拟器通过不是主力机/OEM通过。

### 3.3 本轮不做

- 不做资源版本变化的 B 路径，不构建 B 测试包；不改变 DATA_VERSION、schema 或字典。
- 不做 R01—R12 全量故障注入、随机 kill、部署中断、断电/磁盘故障或长期性能测试。
- 不改正式 `RimeEngine` 生命周期/flush 策略、部署格式、键盘/候选/符号交互或默认惯性与禁回弹。
- 不给正式 APK 开启 debuggable、增加导出 Activity/Provider/广播/探针或测试故障按钮。
- 不新增用户词库管理、方案导入、主题、尺寸设置，不进入 D7/C1。
- 不安装、强杀、降级或清理用户手机；不访问真实私人词库；不正式发布新用户APK。

如果本轮暴露生产缺陷，只记录并停止相关链路；另补修复任务书或范围修订，不能在冻结包实验中偷偷修生产代码、替换 APK 后沿用旧结论。

## 五、安全红线与停止条件

### 5.1 设备与执行授权

- 仅本工作流新建的可丢弃API36/x86_64模拟器；每个独立repeat重新建立AVD，不恢复应用数据、克隆学习结果或复用旧快照。
- 每次运行重新检查：main手动工作流、disposable标记、固定serial、qemu、API/ABI、root UID0、足够存储及已安装包状态；不能沿用上次能力报告。
- 每个adb动作绑定同一serial；拒绝真实设备、多个目标歧义、意外已安装正式包、异常路径及符号链接。门禁不满足即停止，不改为扩大正式包调试权限或清空未知设备。
- 只能修改本轮自建模拟器的IME选择/网络设置；无外部账户、联系人、真实剪贴板和个人数据。开始时确认正式包不存在；若不干净，销毁该实验环境重建，不自动降级/清包“修复”。

### 5.2 冷态数据边界

“键盘收起”“结束输入”“RimeEngine.close/reset”不等于native finalize。冻结release没有提供全局关闭测试接口，本轮也不增加该接口。

本轮固定冷态过程为：结束人工输入并确认无组合 → 收起/离开编辑器并切到测试环境原有其他IME以解绑絮雨 → 在该临时模拟器停止正式包 → 确认该包主进程及所有 `:suffix` 进程完全消失 → 才可复制其人工 `files/rime/` 等允许目录。记录停止方式和进程身份，采集前后再次确认无进程重启；若自动重连/进程未退出，废弃该次副本并停止链路。

- 停止进程的作用是证明OS句柄已释放，**不伪称应用调用了NativeRime.shutdown或正常退出保证flush**。
- 此步骤包含指定的应用进程停止，仅限测试环境；它不是本轮额外安排随机输入中断/部署中强杀，也不能覆盖D6-P5全部场景。
- 允许的源数据访问只有：确认冷态后、对白名单路径内人工数据做只读摘要/复制；不得在线读、散列或复制LevelDB。
- 例外写入仅限冷态下新建本轮sentinel/注释配置；须确认目标原本不存在并校正所有者和SELinux上下文。不得改写数据库、version或部署事务来令测试通过。
- 升级过程只有真正的包替换：不卸载、不 `pm clear`、不 `install -d`、不恢复旧备份、不从观察器回灌。

### 5.3 观察器不制造通过结果

现有debug probe会cleanup sessions并通过librime安全导出；NativeRime.initialize也可能部署和改写副本。因此其证据必须标为“冷态副本的逻辑检查”，不是完全无副作用的数据库读取。

- 分离“未打开的原始冷态副本”和“观察用工作副本”，用快照清单/哈希将观察结果绑定到检查点；观察器只打开由该检查点快照生成的全新工作副本。每个run/repeat/Tn独立封存原始快照；报告只接收白名单结构化结果，不包含原始快照、工作副本或完整导出。
- 观察器不向副本执行候选选择、commit、学习、词库导入/恢复或合成学习数据；不对源应用执行flush/sync/export；不把副本写回源目录。
- 观察器使用与冻结包兼容的librime、schema、字典与reading规则，在专用串行worker和全新进程运行；结束时清除临时完整导出。
- 校准必须同时覆盖“已知有效零记录”“已知正记录”“缺失/损坏/不可读副本或导出失败”。只有冻结包实际使用的目标库在原始快照中存在、有效，且完整导出后确认没有目标记录，才可报T0=0；错误不能被解析为0，更不能自动新建空库、替换目标库或用不重叠造数目录假报负对照通过；无法可靠区分即阻塞本轮。
- 不对捕获的源目录/证据副本调用部署recover/restore来隐去不一致；先验证实际事务状态，只对隔离工作副本执行有记录的必要native初始化。

### 5.4 失败和隐私

- 人工词组/符号以固定fixture ID引用；不上传完整DB、TSV、AVD userdata、全量logcat、bugreport、无筛选目录或设备凭据。
- 输出白名单：版本、APK/资源哈希、测试设备参数、UID、进程身份、检查点ID、文件名/大小/哈希、计数、reading/提交断言结果及错误类别。
- 安装失败、词条记录丢失、观察器不可信、状态混合、超时或目录权限异常，均保留脱敏失败证据并停止；不删断言、不跳过核心检查、不循环重跑直到碰巧成功。
- 修复后重跑使用新case-id和新环境，旧失败保留。证据显示生产问题时，先提交问题和任务书修订，不在本批扩张为生命周期重构。

产出测试状态机和检查点清单。若实现必须改变本书范围，先修订再实施。

### WP1：独立UI夹具与副本观察器

建立外置输入框和自进程runner，通过UIAutomator定位正式包键盘，验证文本与composing span状态。输入动作只能来自键盘按键/候选；允许重建或清空夹具自己的输入框以隔离步骤，不得把预期正文写入输入框冒充提交。

观察器先在自身独立人工fixture验证零/正/错误路径和“观察不新增学习”；不得拿正式release来源进行写入校准。正对照由独立的测试造数步骤产生，读取观察器本身仍不得学习/提交；造数目录不得与任何release快照或其工作副本重叠。全部观察结果与副本ID/校验清单绑定，不接受来自前一轮的结果文件。

**门槛G1**：外置夹具/runner编译和编辑器断言机制校验通过；观察器可区分0、正记录与错误，且不依赖正式app debug入口。具体release真实输入在G2验证，不能在尚未安装145时提前声称已通过。G1失败则不进入release数据/升级实验。

### WP2：全新环境安装原始145并首次输入

每个repeat：新建模拟器 → 安全门禁 → 安装前身份复核 → 安装145及夹具/观察器 → 记录系统语言/字体/密度/存储/页大小和已安装版本UID。

关闭并验证模拟器Wi-Fi/蜂窝网络不可用；构建和下载网络发生在宿主，不借此假装设备已离线。以真实IME按键输入英文，切中文并选择普通候选，确认正文上屏且组合结束。记录active IME包及版本，不能误用系统键盘。

先不提交目标人工词，结束输入/冷态采集 `T0`；观察器应确认目标 `你好你好 / ni hao ni hao` 的stored commits=0。除确认不在内置固定词条外，必须有实际负对照，不能把“候选可合成”视为已经学习。

**门槛G2**：145离线输入、首次部署、T0有效负对照通过；reader缺库/损坏不能算0。G1只校准夹具断言机制，A01所需的真实release输入证据在本步取得，失败则不能进入学习或升级。

### WP3：真实学习、旧包冷启动与保留标记

重开145，使用真实键盘输入 `nihaonihao` 并选择目标候选，固定连续完成三次。每次断言编辑框收到目标正文、无composing span；缺候选、误点或重复提交均失败，不改用直接调用引擎来补学。
