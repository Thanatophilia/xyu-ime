## 已确定的交互

- 展开／收回采用宽口、圆端点折线图标，保持固定点击区。
- 左栏是实际候选首音节筛选，包含“全部”，选中项有底色；首音节栏可独立滚动。
- 左下固定“全部／单字”二态切换，无“词语”模式。单字按完整候选 Unicode 码点数为 1 判定。
- 右侧保持原生候选顺序及全局索引，先按首音节与字类筛选，再由 UI 每页显示最多 9 项。词长决定单元宽度。
- 右栏从上到下固定：删除、上翻页、下翻页、回车，无额外页码指示。翻页只更新 UI 局部状态，按 candidateRevision、selectedSyllable、wordFilter 重建第一页，不向 Rime 发翻页按键，也不改变编码或引擎高亮。
- 到达已加载列表最后一个本地页，且引擎仍有更多候选时继续读取候选前缀。首音节栏末端仍可发现后续分组，沿用最多 4096 项的引擎前缀上限。
- 点击候选按原始全局索引提交并检查修订；右栏回车提交真实高亮候选，越界则不执行，保留 candidateSession 保护且不触发编辑器发送／搜索。
- 删除只编辑当前未提交拼音，支持长按连删，删空后不波及已提交正文。
- 独立悬浮编码保持在键盘物理左上方；展开页继续替换整个下方键盘，包括原底部七键，应用窗口和 IME 布局不变。
- 本轮只修改 app 模块和测试，不改引擎、资源、方案与构建。旧版本 0.3.55 的三态类型／清空／返回交互由上述已确认布局替代。

## 暂缓的候选页能力

- 长按候选查看详情、把候选标记为不再推荐、删除误学词等能力需要区分普通词典候选和用户学习词。当前引擎桥接未暴露学习词删除接口，且误删普通词库候选没有意义；应单独设计确认交互和引擎接口，不在本轮用假删除实现。
- 滑行输入、语音、Emoji 面板、九宫格属于后续阶段，不在本页范围。

## 读音来源与边界

通过 librime 公共候选迭代 API 同时复制 `text` 和 `comment`，以成对数据交给 Kotlin，空注释保留空槽，避免索引错位。内置全拼方案开启 `spelling_hints` 与 `always_show_comments`，由 script_translator 从词典 syllable code 生成实际拼写；不对汉字另做猜音，也不把输入串复制到每个候选上。

拼音栏按候选首音节分组，例如 `ni hao` 归入 `ni`。这属于对真实候选的首音节筛选，并非九宫格消歧，也不是逐音节改写 Rime 的输入。缺少拼音信息的候选仍可在“全部”找到。

读音支持已在 0.3.54 同步更新方案版本与资源哈希，并通过部署事务保留用户目录；本轮不更改方案或资源，继续保留升级失败恢复机制。

## 回归重点

- 多读音候选使用当前引擎路径的真实拼写，扩展加载保持文字/拼音一一对应。
- 筛选后选中非零全局索引的词条，实际提交与所见文字一致。
- “全部”恢复第一页候选；有界按钮翻页收集 All 页面后，以索引和文字核对音节与单字子集；每个单字模式条目只含一个码点。
- 普通键盘与底部七键在展开页不可见；收回恢复；保留既有浮窗、回车、编辑功能回归。

- 拖动不要求改变候选，但必须保持展开、不选词、不提交、不露普通键。候选回车验证组合结束、提交前缀保留、编辑器动作为空，不假定词典返回哪一个词。
