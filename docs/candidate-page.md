# 展开候选页优化

交付：**0.3.54**，代码 `741f9d7`，[Actions #54](https://github.com/Thanatophilia/xyu-ime/actions/runs/43961010664) 完整回归与签名/双 ABI/对齐检查通过，用户实机审查待完成。53 项测试通过（app JVM 25、部署套件 1、app Android 21、Rime Android 6）；该计数不代表所有 ROM 或全部阶段三验收通过。

## 已确定的交互

用户要求展开/收回箭头开口更宽、替换尖角字符图标；经确认，候选页采用**左侧拼音/音节栏，右侧对应汉字候选**。

- 右侧固定展开/收回按钮改为宽口、圆端点折线图标；点击区和向下展开动画延续既有规则。
- 左侧拼音栏竖向滚动，包含“全部”和实际候选首音节，选中项有底色区分。
- 右侧候选按词长占用不同宽度，保持 Rime 候选顺序；筛选使用原始全局索引上屏，不重新编号。
- 选音节只改变本页筛选，不提交、不改写原始编码；每次点音节或“全部”均回到候选顶部，包括重复点当前项。同一组合收回再展开保留筛选与滚动位置，输入变化或部分选词后重置为“全部”。
- 到达拼音栏或筛选候选末尾时继续读取引擎后续候选前缀，不能将当前已加载部分误当成完整候选集；沿用当前引擎最多 4096 项前缀的上限。
- 独立悬浮编码仍在键盘左上方；候选页展开仍替换整个键盘，包括原底部七键，不改变应用/IME 布局。

## 读音来源与边界

通过 librime 公共候选迭代 API 同时复制 `text` 和 `comment`，以成对数据交给 Kotlin，空注释保留空槽，避免索引错位。内置全拼方案开启 `spelling_hints` 与 `always_show_comments`，由 script_translator 从词典 syllable code 生成实际拼写；不对汉字另做猜音，也不把输入串复制到每个候选上。

拼音栏按候选首音节分组，例如 `ni hao` 归入 `ni`。这属于对真实候选的首音节筛选，并非九宫格消歧，也不是逐音节改写 Rime 的输入。缺少拼音信息的候选仍可在“全部”找到。

方案版本与资源哈希同步更新，通过已有部署事务保留用户目录；升级失败时保留恢复机制。

## 回归重点

- 多读音候选使用当前引擎路径的真实拼写，扩展加载保持文字/拼音一一对应。
- 筛选后选中非零全局索引的词条，实际提交与所见文字一致。
- “全部”恢复候选，选音节不改变编辑框正文、悬浮编码、窗口和键盘高度。
- 普通键盘与底部七键在展开页不可见；收回恢复；保留既有浮窗、回车、编辑功能回归。
