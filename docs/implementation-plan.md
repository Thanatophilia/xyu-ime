# 絮雨输入法完整实施方案

更新：2026-11-18。代码基线 `b3b0e05`，APK **0.3.72**，路线归档基线 `d3d1a85`。用户已确认 0.3.72 上一轮改动实机验证无问题。本文件是后续实施方案，不表示下面的功能已经开工或交付。

本方案与[路线总览](roadmap.md)、[测试与验收矩阵](verification-plan.md)一起使用。原阶段三任务书保留为历史设计，当前状态以路线总览和最新实机反馈为准。

## 1. 最终目标和推进原则

先交付一款可以持续日常使用的离线中文输入法：英文、中文、编辑操作与特殊输入框行为可靠，升级保留用户词频，系统回收或部署失败后可以恢复，安装包可追溯。此后逐步提供可恢复默认值的个性化设置和受控 Rime 扩展。

技术方向固定为 Kotlin + InputMethodService + InputConnection + Jetpack Compose + librime/JNI。构建与测试仍在 GitHub Actions 执行，每个可验收版本交付固定签名 APK，由用户自行安装审查。

实施规则：

1. 对已有能力先写行为说明、执行验证；只有证据显示缺口时才改代码。每个问题保留输入步骤、期望、实测、修复及回归结果。
2. 当前候选交互是基线：独立悬浮编码、固定候选栏、展开覆盖整个下方键盘、固定最左首屏接续、横滑动画收回、单字五列、词语紧凑混排、两侧等宽、图标与手动连续滚动。后续变化必须有具体需求或可复现问题。
3. 基础功能先于自定义。符号页重排属于基础体验工作，但具体布局在实现前先提供可审查样稿；不擅自改七键顺序。
4. 维持无网络权限、不记录输入正文、密码直输、无后台剪贴板读取。诊断只用人工测试文本和不含输入内容的统计。
5. 一包解决一组相关问题。云端完成后给 APK、变更列表和短验收卡；收到实机反馈后再归档结论。

## 4. 阶段四：日常输入完善

### P0：封存基线，建立可执行行为表

**要做什么**：把“已经通过”和“还有哪些证据待补”写到同一套表中，避免阶段状态反复倒退。

**实施**：

- 在路线、验收清单中固定 0.3.72 用户确认；把旧 `phase3-progress.md`、`candidate-page.md` 的历史版本状态标明为历史，并链接到当前状态。
- 从 `dispatchAction`、`finishRaw`、`onUpdateSelection`、`pauseViewLifecycle` 逐项整理行为表；每行写触发动作、原组合、提交结果、编辑器动作、候选/浮窗状态。
- 执行现有 JVM 和 Android 用例，记录实际报告。旧的“80 通过”仅指 0.3.72，后续不固定沿用计数。
- 对 0.2.32 句号后大写补一次明确复测记录：句号/感叹号/换行/连续空格，以及手动 Shift 覆盖。此项是旧验收记录补齐，不阻塞已通过的候选交互。

**完成标准**：每项现有能力有出处；没有把已有代码重新列为待开发；无证据的边界行为只标待验证。

### P1：更新应用引导及试打工具

**确定需要修改**：`MainActivity.SetupScreen` 仍显示 `XYU / PHASE 02`、“基础编辑测试版”“当前仍为 English”，文本试打标签也写“输入英文”。改为与当前离线中英文能力一致的说明，版本/提交继续从 BuildConfig 读取。

**实施**：

- 保留启用/选择输入法入口与 13 类试打类型。把“当前能力”和“本版变更”分开，减少每次发包修改多处文字。
- 补多行中文、发送、下一项/上一项、两个输入框切换的试打场景；发送动作只在本地计数/显示已收到，不发送真实消息。
- 在测试变体加入原生 EditText 与 WebView/contenteditable 夹具；故障注入、延迟回调等入口只留在测试代码或 debug 变体，发布 APK 不提供破坏性测试按钮。
- 使用固定人工文本演示组合输入、长句、选区替换和 emoji。沿用试打内容不保存、离开清空；不自动读取用户剪贴板。

**验收**：引导步骤真实有效；所有标签与实际能力一致；切测试类型后内容/动作计数隔离；输入法布局和系统 Insets 不被试打页改动影响。

### P2：中文组合输入、编辑与动作队列

**当前策略先保留并验证**：点击编辑工具或进行编辑操作前，现有服务通过 `finishRaw` 结束组合；外部光标/选区变化会使旧引擎结果失效。拼音中间光标编辑尚不是已交付专用功能，本批先保证末尾修改和结束组合后的正文编辑可靠。

**实施顺序**：

1. 在测试中控制引擎响应延迟，覆盖“尚未返回首个预编辑时移动光标/切框”和“队列中已有按键时切语言”。验证旧会话输出被丢弃，普通输入动作顺序不乱。
2. 测试整句拼音、逐词选择后的剩余拼音、输入末尾删除/补字母、撇号切音节；不要依赖词库恰好产生某个固定首选词，候选提交按引擎返回的实际条目断言。
3. 测试有组合时进入编辑面板、移动光标、全选/替换、复制剪切、主动粘贴，再返回中文输入；检查一次动作只结束一次组合，没有重复原始拼音或误删已提交前缀。
4. 测试普通删除与候选页长按删除的区别：候选工具删空拼音后停止；普通删除仍按既定正文删除规则。测试拖出按键、收起键盘、切框和旋转时重复手势正确取消。
5. 发现问题后优先在服务现有队列与 `ChineseSession` 边界修复。若测试替身难以注入，提取最小引擎接口/动作处理边界，不改写已稳定候选布局。
6. 对无效 InputConnection、接口返回 false/null 的编辑器提供不崩溃的降级；不在未知文本范围上猜测并删除内容。

**交付**：组合态行为表、异步输入/编辑回归、修复说明、实机验收卡。验收矩阵使用 I01—I08、E01—E05。

**完成标准**：没有丢字、重复提交、旧候选上新框或删除已提交内容的非预期行为；与当前基线不同的可见输入规则必须在变更说明中写明。

### P3：特殊输入框、中英文和标点

先依据当前代码形成如下默认规则；这是本方案保留现有行为的建议，若后续产品规则调整，先改表再改代码和测试。

| 动作/场景 | 建议保留的明确结果 | 测试重点 |
|---|---|---|
| 中文组合 + 空格 | 由 Rime 选择候选；无组合时输入普通空格 | 连续空格、选词后仍有剩余拼音 |
| 普通回车 + 组合 | 只提交原始拼音；不同时发送/搜索/换行 | 第二次无组合回车才执行编辑器动作 |
| 候选页右侧回车 | 提交引擎当前有效高亮候选 | 过期会话或无效索引不提交 |
| 中文组合 + 逗号/句号 | 先提交当前候选，再写中文标点 | 正文前缀保持，不重复标点 |
| 中文组合 + 数字/其他符号 | 按当前 `finishRaw` 先完成原始拼音，再插入字符 | `nihao123`、括号、问号的实际结果可解释 |
| 切数字/符号页 | 页面切换本身保留组合，后续字符依照上面规则 | 切回字母继续拼音、撇号分词 |
| 切英文/中文 | 有组合先按现有规则提交原始拼音，再切语言 | 有排队按键、准备词库完成时不抢输入 |
| Shift/大写锁定 | 保留现有状态语义，大写字符直输前结束组合 | 单次 Shift、锁定、回切中文 |
| 密码/数字/电话/网址/邮箱 | 按 `EditorPolicy` 路径选择页面和 ASCII 标点，受限框不进 Rime | 编辑器变化后敏感标记及时更新 |
| NO_PERSONALIZED_LEARNING | 当前实现禁用中文引擎，安全直输 | 明确提示；若未来改为“中文但不学习”，需引擎能力和数据验证另立工作包 |

**实施**：补 EditorInfo 的 actionId/actionLabel、自定义 action、多行与 NO_ENTER_ACTION、下一项/上一项的场景；根据 `EditorPolicy.enterAction` 的实际结果和 Android 约定验证，必要时修复。对于框类型不可信的第三方编辑器，记录限制并优先避免执行不可撤销的发送动作。

**完成标准**：每类输入框的初始页、标点、中文可用性、回车行为都有测试证据；“组合 + 回车”没有触发多余发送。普通文本框的语言偏好是否跨服务重启保存放到 C1 设置中处理，本批不偷偷增加持久化。

### P4：窗口、兼容性、触控与无障碍

**实施**：

- 建立三种编辑器夹具：原生 EditText、Compose TextField、WebView 的 input/textarea/contenteditable；各自验证输入、选区、回车和切框，不能只以自家试打页推断第三方应用兼容。
- 在真实 IME 窗口记录普通键盘/展开页/编辑面板的边界和 Insets；竖屏、横屏、分屏受限高度、字体缩放 1.0/1.3/1.5 下检查布局。底部系统区域使用真实 Insets，不叠加 OEM 硬编码偏移。
- 在 realme 标准/抬高两档复测，保留系统原设置；旋转后独立编码窗口重新定位，不残留、不抢焦点。横屏高度不足时优先可操作，不能为保证五列而把文字裁切或制造重叠触控区；需要改变布局规则时先提交问题截图与方案。
- 验证 TalkBack 能描述语言、Shift/锁定、候选、筛选选中态、不可用滚动图标和编辑工具。所有重要动作通过语义操作可达；关闭动画或系统触觉不影响功能。
- 检查连删取消、手指拖出按键、多指交错、候选滚动与点击判定。通过实际设备验证触控区域，不仅检查 Compose 声明尺寸。

**验收**：系统区域不被侵入；候选出现/隐藏不改变字母键尺寸；展开候选/编辑面板不额外顶高应用；主力设备连续使用无残留编码窗口；可访问名称和操作状态与画面一致。

### P5：符号页重排与常用符号

这是用户已提出的后续需求，目前只有固定符号数组和页面，没有已确认的新布局。方案流程必须具体：

1. 盘点当前数字页/符号页字符、重复项、遗漏的常用中文标点；记录每个字符的原样文本、类别、页面位置。
2. 提供同尺寸静态样稿或可点击原型：建议“中文常用 / 英文常用 / 数学与单位”分组，明确分类入口、删除/回车/返回字母、底部七键关系。每项字符都展示，不能只写“优化布局”。
3. 用户定稿后，把字符与分组做成数据模型，界面只渲染；保持输入事件进入现有控制器。数字专用输入框继续按 `numberKind` 展示合法常用字符。
4. 第一批做稳定的分类与直接输入，不默认增加“最近使用”、配对自动补全、长按弹层或云符号库。需要这些行为时单独规定光标、组合态和记录策略。
5. 验证中文组合下输入符号、空组合输入、连续标点、长符号、切回字母、横屏与大字体；符号文本不得因显示标签而被错误替换。

**交付**：完整字符清单、定稿样稿、符号配置数据、APK 与短验收卡。完成后阶段四可形成日常输入候选版；不要求等待自定义能力。

## 5. 阶段五：稳定测试版

### S1：用户数据和真实升级

已有 `RimeDeployment.begin/commit/recover/initialize`，会在原生数据库关闭时备份用户/旧共享数据，并在失败或中断后恢复。保留这套机制，先验证真实升级结果。

**实施**：

- 用可丢弃模拟器/独立测试用户安装旧的固定签名包，使用人工词组反复选词，记录学习效果；正常结束输入，重启后确认已持久化。
- 覆盖安装新包，不卸载、不清数据，确认 packageName、签名不变和 versionCode 增长。测试“仅 app 变化、数据版本不变”及“测试构建的数据版本变化”两条路径。
- 稳定证据不只比较候选排名：排名还受词典影响。应使用引擎支持的用户词记录查询/导出或测试用持久化探针佐证；若当前 JNI 不支持，增加仅测试可用的观测方法，不把真实个人词库上传为 artifact。
- 检查升级后用户词仍可使用、重启后保留、旧数据没有被打包资源覆盖；备份清理符合事务状态。
- 明确系统备份策略和排除项，审查 Manifest/backup rules；不得把数据库备份到何处、能否跨设备还原留成隐含行为。用户可见导入导出放 C4。

**验收**：旧→新覆盖升级及重启后人工学习词保留；资源版本改变和不改变均有报告；不能用“同签名能安装”代替数据迁移验收。不要在用户主力手机上自动清数据或强制做降级覆盖。

### S2：部署、进程与故障恢复

**实施**：

- 沿用部署 JVM 故障注入，补测试进程在备份、pending、资源部署、版本写入、committed 后清理各阶段终止；重新启动后验证恢复幂等和旧词库可用。
- 在测试变体注入资源校验失败、部署异常、数据库不可用、存储写入失败；停止原生数据库之后才允许恢复文件。发生原生 shutdown 失败时不得继续对打开中的库做复制还原。
- 验证首次启动失败仍可英文直输，明确中文不可用状态并允许主动重试；避免自动无限重试与重复弹提示。
- 验证组合尚未提交时隐藏/重开、切输入框、系统回收和正常重启；已上屏文本由目标编辑器保存，输入法不把未知旧组合补发到新框。
- 若测试发现现有错误路径仅显示笼统错误，增加无正文的错误分类与本地状态说明；保留离线可用、不要强制上传日志。

**完成标准**：没有数据库破坏、事务半提交、重复部署死循环或跨框补发；失败时英文路径仍可用；恢复至少重复执行两次仍得到一致结果。

### S3：性能与资源占用

先采基线再定优化。测试在同一设备、系统设置和构建类型下执行；冷部署、冷启动、热输入、候选扩展分开统计，不拿模拟器数值宣传真机性能。

**采样方法**：release/profileable 测试构建，人工固定文本；热按键/候选更新至少 100 次，冷热启动各 10 次，打开关闭及切框各 100 次。记录触控到渲染帧、worker 耗时、主线程阻塞、PSS、线程数和候选加载量；不得记录正文。

**初始验收目标（需基线测量后固化）**：

- 主力设备热输入触控到对应预编辑/候选帧 P95 目标 ≤100ms；若现状超过，先定位部署、JNI、候选生成与 Compose 各段，不以隐藏错误/丢弃输入“提速”。
- 同设备同脚本候选动画与快速输入较 0.3.72 的 P95 不回退超过 20%；超出必须解释并给出处理结果。
- 首次部署期间英文可输入，UI 不因同步部署卡住；记录首次准备耗时和可用存储，不在没有测量时承诺固定秒数。
- 100 次循环后不残留活动预编辑窗口或不断增加的引擎线程；两轮稳定后内存应趋稳，若持续增长需堆/对象证据定位。单次 PSS 波动不直接判泄漏。
- 候选按需加载保持有界，现有最多 4096 项前缀作为已知限制保留；不为大列表一次性构建全部候选视图。

发现问题优先减少重复快照、重复重组和不必要分配，保留串行原生调用及提交顺序。每项优化必须有前后同脚本数据。

### S4：兼容性矩阵与持续试用

- 当前 CI 主要是 Android 36 x86_64；扩展为快速门禁与扩展回归两层，见测试矩阵。最低声明 API 26 必须有实际安装/启动/输入记录，避免只靠 minSdk 声明。
- 16 KB 分两种证据：APK/ELF 静态对齐沿用现有 verifier；实际 16 KB 内核上需确认页大小并加载引擎、离线输入。没有相应环境时明确列为未验证，不把静态通过写成运行通过。
- 日常试用建议连续 7 天，覆盖聊天/浏览器/备忘录，每次只收集版本、设备、场景、操作和可公开的人工复现。测试时长是覆盖建议；发布门槛以问题和证据为准，不宣称七天可证明没有缺陷。
- 阻塞问题（崩溃/ANR、误发、跨框提交、学习数据丢失、不可输入）清零；高频影响输入的问题清零；其余限制有复现、影响、临时处理和后续安排。

### S5：稳定包发布与交付工具

- PR：编译、JVM、Lint、核心模拟器回归；不读取签名 Secrets。主线：完整测试后构建固定签名 release APK，做 release 安装/启动/离线输入冒烟，不能只测试 debug 包。
- 扩展回归和升级链路放手动或计划工作流，先确保失败可复现再决定是否加入每次门禁。冷缓存构建至少在原生依赖/NDK/工具链变化及稳定版前运行一次。
- release 文档从构建元数据和本次变更生成，不再将固定阶段三旧清单作为所有后续版本 READ-ME。包内含 APK、SHA256SUMS、版本/提交/时间、变更、验收卡、已知限制、静态校验报告。
- 核对依赖与词典许可证、来源和版本锁定，提供 NOTICE/许可文件入口。已有 Lint 警告按影响分类处理，不能简单压低统计或一律忽略。
- 候选稳定包通过后准备 tag/Release 草稿，核对签名、哈希和资产一致，再按发布授权正式发布。不重置用户设置、不重新生成签名密钥。

**阶段五完成标准**：核心输入、兼容矩阵、升级/恢复、性能与实际使用证据齐备；阻塞问题清零；安装包与文档一致；未覆盖设备和已知限制透明列出。稳定版本号在执行 S5 时统一确定。

## 6. 基础稳定之后：自定义与 Rime 扩展

按依赖顺序分四批交付，避免“自定义”变成无边界重写。以下为建议范围，具体界面和可调值在各批实施前出样稿。

### C1：设置基础与可恢复默认值

1. 增加统一 `KeyboardPreferences` 模型、Repository 和 DataStore 持久化；UI 通过快照读取，磁盘写入不阻塞输入线程。设置与 Rime 用户数据库分开。
2. 为每个字段定义默认值、合法范围、迁移版本。新字段有缺省，坏值回落默认；旧设置升级不丢失。重置设置只重置外观/偏好，不能清除学习词频。
3. 第一批只开放风险低、影响明确的项目：跟随系统/浅色/深色，系统触觉反馈开关，默认输入语言偏好。键盘当前已有自动深浅色和系统触觉，本批增加用户控制和持久化。
4. 语言偏好仅适用于允许中文的普通文本框，密码/数字等仍由 EditorPolicy 优先。记录“用户选择”与“框类型临时覆盖”的区别，离开密码框后不应把临时英文强写成永久偏好。
5. 设置页提供当前值、即时预览、恢复默认说明；修改后跨键盘重开和进程重启保留。多次快速修改不使旧配置覆盖新配置。

**验收**：安装默认行为与基线一致；设置重启保留；坏配置可恢复；主题和触觉开关不会影响提交；恢复默认不触及用户词库。

### C2：尺寸和触控反馈

1. 从 `KeyboardGeometry` 和 `KeyboardView` 提取统一尺寸配置，竖横屏分开；按可用窗口计算并钳制范围，系统导航区始终放在内容之外。
2. 先提供几个有测量依据的高度档位，再考虑连续滑杆；范围由最小触控尺寸、大字体和横屏可用高度共同决定，实施前提供档位样稿与实测尺寸表。
3. 所有普通页、编辑面板、展开候选页共享键盘主体高度；独立编码只重新定位，不能参与撑高应用。宽度变化后重新测量候选接续边界。
4. 触觉第一版沿用系统反馈常量；用户要求强度自定义时再评估 VibratorManager、设备能力和功耗，不能把系统反馈常量假装成可精确控制毫秒/强度。
5. 设置预览可撤销并恢复默认；极端参数不能让功能键移出边界。单手模式、左右留白、自定义键间距另立设计，避免与等宽和七键布局规则冲突。

**验收**：所有档位、方向、系统位置和字体倍率组合可操作；底栏和候选页两侧等宽关系仍成立；从非法旧值恢复后无需清数据。

### C3：布局、长按与候选偏好

先确定可编辑边界，再写配置格式。第一批建议从符号分组内容和常用符号顺序开始；普通七键布局、地球长短按等既定操作默认保持。

- 每个键使用稳定 ID、显示标签、主动作和可选长按动作；布局配置包含版本号与必需键校验，不能只有字符串数组。所有动作经过服务控制器，不允许配置直接调用任意系统命令。
- 设置编辑器提供预览、冲突说明、保存/取消、恢复默认。缺删除/回车/返回入口或触控面积不足的配置拒绝保存并说明原因。
- 如加入长按符号弹层，先定义：按住时出现、滑动预选、抬手提交、滑出取消、多指与系统中断取消；弹层不抢编辑焦点，未完成选择不提交，TalkBack 有等效入口。
- 如开放候选字号/显示偏好，使用现有测量布局重新计算混排与固定接续，不能只修改文本字号导致索引、行宽或侧栏出界。动画关闭选项需保证输入与候选点击仍正确。
- 用户配置导入是数据操作，使用版本校验、大小上限和合法动作白名单；先在内存验证再原子替换，失败保留旧配置。

**验收**：默认配置与 0.3.72 交互兼容；编辑取消不生效；坏配置/旧格式可回退；长按不同时触发短按；自定义不会绕过密码和会话保护。

### C4：用户词库、方案与引擎扩展

这批不直接承诺“任意 Rime 方案均兼容”，按能力逐步开放。

1. **只读状态**：显示当前引擎/数据版本、方案 ID、最近部署结果和用户数据位置说明，不展示私人输入内容。提供重新部署入口时，明确其保留用户学习数据。
2. **用户词库备份/恢复**：通过系统文档选择器由用户选文件；在 worker 暂停输入并关闭原生数据库后取得一致快照，或使用 Rime 支持的同步/导出机制。定义包版本、清单和校验和；恢复先校验兼容性、备份当前数据，再事务切换。导出包含个人词汇，界面说明并让用户自行选保存位置，不默认上传。
3. **词条管理**：先验证 librime 的删除/学习接口和持久化语义，再设计长按候选删除学习词。只能删除用户学习条目，不能把当前候选文字误当成全局词条 ID；内置词典条目与用户词明确区分。现有 JNI 尚不提供这项 UI 操作，不能仅加个按钮宣称完成。
4. **内置方案选择**：先接一套明确依赖和许可的额外方案，验证方案切换会话隔离、用户数据命名和回退；繁简切换也须说明依赖的是转换器、词典还是不同方案，并给出转换范围。
5. **受控方案导入**：使用 SAF，校验文件清单/大小/路径，拒绝绝对路径、`..` 穿越和符号链接；在隔离临时目录部署，成功后原子激活，失败仍可用旧方案。限制支持的标准组件、资源和版本；缺插件时显示原因，不修改全局库试图硬兼容。
6. **Lua/其他插件**：只有导入需求确实需要时再独立评估构建、ABI、性能、执行能力、许可证和信任边界。外部脚本不随普通字典导入默认执行。九宫格、滑行、语音和联网同步分别另立产品方案，不捆绑进 C4。

**验收**：备份可验证恢复且当前数据有回退；损坏/不兼容导入不破坏已有词库；方案切换没有旧会话文本上屏；导入能力和限制可解释。

## 7. 每个工作包的开发与交付流程

1. **输入**：工作包编号、当前 main 提交、用户已确认规则、可复现问题/待验证场景。
2. **设计**：先写行为变化和受影响文件。布局变化附完整样稿，数据变化附目录/格式/迁移和失败恢复说明。已有明确规则的常规修复不重复要求用户批准。
3. **实现**：使用小提交或独立分支，先补能揭示问题的最小回归，再修实现；低风险文案和纯文档不添加无意义测试。
4. **云端验证**：按测试矩阵执行相关门禁；失败先区分代码、模拟器环境和测试不稳定，不通过跳过断言来得到绿灯。通过后避免无理由重复跑全套。
5. **交付**：列出实测结果、版本、提交、Actions、APK 链接、哈希、已知限制和 5—8 步验收卡。核心测试包仍由用户自行安装，不自动改用户默认输入法。
6. **归档**：实机反馈对应实际 APK 版本，只把用户确认的内容标通过；更新 README/验收表/路线当前项。代码改动不因只更新文档而伪造新 APK。
7. **问题分级**：P0 为崩溃/ANR、跨框文本、误发送、数据损坏等阻塞问题；P1 为高频基本输入受损；P2 为有明确绕路的体验缺陷；P3 为外观和便利性。P0/P1 阻塞日常候选版或稳定版，P2/P3 按范围和影响安排。

### 建议拆成的交付批次

| 批次 | 内容 | 用户拿到后主要验证 |
|---|---|---|
| D1 | P0/P1：状态统一、引导更新、试打夹具 | 能看到准确版本说明和中文/发送/多框试打 |
| D2 | P2：组合态、编辑及队列问题修复 | 长句、删改、编辑插入、切框、快速输入 |
| D3 | P3：特殊输入框和标点/回车规则 | 中文标点、数字/符号切换、搜索发送只触发一次 |
| D4 | P4：窗口、第三方编辑器和无障碍 | 常用应用、横竖屏、标准/抬高、大字体 |
| D5 | P5：经定稿的符号页 | 字符覆盖、分类、返回路径和中文组合联动 |
| D6 | S1/S2：升级和恢复 | 覆盖安装、学习词保留、重开仍能输入 |
| D7 | S3/S4/S5：性能、试用和稳定包 | 连续日常使用、已知问题收尾、最终版本验收 |
| D8 起 | C1→C2→C3→C4 分批 | 每批一组设置或管理能力，可恢复默认 |

批次可因实际问题合并，但不把高风险升级测试与全新布局一起交付。工期在 P0 基线/缺口核对后按工作包估算；云端失败、第三方编辑器差异、实际 16 KB 环境和方案插件兼容是主要变动来源，暂不承诺无证据的日历工期。

## 8. 紧接着应执行的第一批任务

当用户授权开始实现时，先执行 D1，然后进入 D2：

- 统一 README、阶段三状态和旧进度页入口，以 0.3.72 为实机已通过基线。
- 更新 MainActivity 旧阶段与 English 文案；保留已有 13 类入口并补中文、多框、发送验证。
- 建立原生/Compose/WebView 夹具和 P2 异步回调测试所需的最小接口；先确认已有测试覆盖，避免重复搭框架。
- 从测试矩阵 I01—I08、E01—E05、F01—F05 逐项跑现状。发现问题形成清单，修复有证据的问题，记录不用改代码的已通过项。
- 发第一批可安装包和短验收卡，明确后续优先修哪组行为。符号页样稿、自定义范围和新方案不混入这一批。
