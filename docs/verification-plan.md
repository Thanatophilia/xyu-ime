# 絮雨输入法测试与验收矩阵

对应[完整实施方案](implementation-plan.md)。0.3.72 的用户实机通过结论保持；本矩阵规定后续改动如何验证，不把新增用例自动当作当前版本缺陷。每个新包记录真实执行范围、环境、结果与未覆盖项，不预先勾选全部通过。

## 1. 环境和执行频率

| 层次 | 环境/执行内容 | 频率 |
|---|---|---|
| 快速门禁 | JVM 策略/会话/布局计算、部署事务；编译、Lint；现有 Android 36 x86_64 引擎和真实 IME 核心测试 | 每个相关 PR/代码主线 |
| 扩展兼容 | API 26、30、35、36；原生/Compose/WebView 夹具；横竖屏和大字体 | 对应兼容改动、阶段候选包、稳定版前；不强制每个文案变更全矩阵 |
| 发布冒烟 | 实际固定签名 release APK 安装、启动、启用/选择、英文、离线中文、回车、隐藏重开 | 每个交付 APK |
| 主力真机 | realme RMX3852 / Android 16 / arm64；标准和抬高、手势导航，聊天/浏览器/备忘录 | 相关版本由用户验证，记录实际应用版本 |
| 数据升级 | 旧签名 release→新 release，同数据版本/数据版本变化，持久化学习词与恢复 | 部署/引擎/资源/数据改动及稳定版前 |
| 工具链 | 双 ABI ELF/ZIP 16 KB 静态检查；无原生/Gradle 缓存构建 | 静态检查每个 APK；冷构建在工具链变动及稳定版前 |
| 16 KB 运行 | 实际报告页大小为 16384 的受支持设备/模拟器，原生加载和离线输入 | 原生改动及稳定版前，有环境才记录为运行通过 |
| 长期/性能 | 同一真机的固定人工输入脚本、100 次切换、连续试用 | 性能/状态改动、阶段候选包 |

API 26 是最低声明系统；若当前模拟器镜像不支持相应 ABI，选择可运行的镜像或真机，不伪造执行结果。测试夹具与框架版本也须支持目标 API。应用目前无网络权限，WebView 夹具使用本地 HTML。

## 3. 结果归档格式

每条记录包含：用例编号、APK版本/提交/哈希、设备与API/ABI/内核页大小（相关时）、输入框或应用版本、设置、人工步骤、期望、实际、通过/失败/未执行、报告/截图路径、问题编号。

仅使用人工测试字符串。JVM/JUnit/Gradle HTML/设备日志各自标明来源；套件入口与内部断言不能混算通过数量。未执行写原因和后续条件，不能用空勾选推断失败，也不能默认通过。

## 4. 每个APK给用户的短验收卡

从本批受影响用例选择5—8步，不每次要求重测全部矩阵：

1. 核对版本与覆盖安装，打开当前试打入口。
2. 一步验证本批主行为，写可照做的人工文本和预期。
3. 一步验证边界或重复操作。
4. 一步验证切框/收起重开不会串文本。
5. 一步验证0.3.72候选基线或本批相关既有功能。
6. 仅升级相关版本验证人工学习词保留，不要求用户清主力数据。
7. 记录失败时的应用、操作、期望与实际；私人正文无需回传。

## 5. 完成门槛

- 工作包：相关新增/修复场景通过，既有关键回归通过，证据和限制明确。
- 日常候选版：核心输入/编辑/回车/窗口无P0/P1，主力设备本批验收通过。
- 稳定测试版：升级/恢复、兼容矩阵、性能和持续使用结果齐备；阻塞问题清零；实际release包与发布资料一致。无法覆盖的环境单列支持边界，不虚构通过记录。
