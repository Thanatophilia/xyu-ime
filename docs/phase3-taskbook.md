# 絮雨输入法阶段三任务书

版本：阶段三 / M2
项目：Thanatophilia/xyu-ime
编写依据：2026-11-16 当前仓库与历史开发路线

## 一、任务定位

阶段三的目标是把现有的 Compose 英文键盘和基础编辑能力，接入自行实现的 Android Rime 前端，完成一套可离线使用的简体中文全拼输入闭环。

阶段三完成后，用户可以在真实 Android 手机上：

- 在英文和中文拼音模式之间切换；
- 输入拼音并看到预编辑文本；
- 在候选栏中选择汉字；
- 使用空格、候选点击、滑动候选栏、向下展开的候选抽屉、删除和回车；
- 在聊天、浏览器、备忘录等普通编辑框中持续输入；
- 断网使用；
- 覆盖安装新版后保留 Rime 用户词频和用户数据；
- 在密码框、数字框等特殊编辑框中继续遵守现有安全和类型适配规则。

本阶段的技术重点是原生引擎构建、JNI 边界、Rime 会话生命周期、预编辑与候选状态同步，以及输入法服务和编辑框之间的正确提交。符号页重新布局、键盘自定义、九宫格、滑行输入、语音和在线同步不属于本阶段交付范围。

## 四、总体技术方案

### 4.1 模块边界

在现有 `app` 模块之外增加一个 Android library 模块，建议命名为 `:rime-engine`：

- `:app`：`InputMethodService`、Compose 键盘、编辑框策略、输入连接、中文状态展示；
- `:rime-engine`：Kotlin API、JNI、C++ 封装、librime 原生库和 Rime 资源；
- 纯 Kotlin 的按键映射、候选显示状态和输出归并逻辑可以先放在 `app` 的 `ime` 包中，等阶段三稳定后再决定是否拆成独立 `:ime-core` 模块。

不要让 Compose 直接调用 JNI，也不要让 C++ 直接操作 `InputConnection`。输入连接只由 Android 主线程上的服务层使用，Rime 只负责输入状态和输出结果。

### 4.2 引擎串行模型

Rime 会话和部署过程统一由一个单线程 `RimeWorker` 串行执行。每个请求带有递增序号，结果回到主线程后检查输入会话编号；旧编辑框或旧键盘产生的结果必须丢弃，不能提交到新编辑框。

建议输出对象包含：

```text
RimeOutput
- consumed: 是否由 Rime 消费了本次按键
- commitText: 本次需要提交的文本
- preedit: 当前预编辑文本
- cursor: 预编辑光标位置
- candidates: 候选列表
- highlightedIndex: 当前候选索引
- page: 当前页码
- isLastPage: 是否最后一页（不假定引擎已计算候选总数或总页数）
- inputSessionId / sequence: 编辑会话代号和请求序号
- hasComposition: 是否仍有 Rime 组合输入
- error: 可展示但不包含输入正文的错误信息
```

`InputConnection` 的读取、`setComposingText`、`commitText`、`finishComposingText` 和删除操作必须在服务主线程执行。Rime 的初始化、按键处理和上下文读取走 `RimeWorker`，部署绝不能在键盘显示线程上同步执行。

### 4.3 JNI 最小接口

第一版只暴露实际需要的能力，避免把整个 C API 直接暴露给 Kotlin。接口至少包括：

- `initialize(sharedDir, userDir, logDir)`；
- `isInitialized()`；
- `createSession()` / `destroySession()`；
- `processKey(session, keysym, modifiers)`；
- `getContext(session)`；
- `selectCandidate(session, index)`；
- `pageUp(session)` / `pageDown(session)`；
- `clearComposition(session)`；
- `getCommit(session)`；
- `deployIfNeeded()` 或独立部署状态查询；
- `selectSchema(session, schemaId)`；
- `finalize()`。

JNI 层负责 UTF-8 转换、空指针检查、异常边界和 native handle 生命周期。任何 native 崩溃风险都要在 C++ 封装层隔离，Kotlin 层不得保存裸指针。

### 4.4 Rime 版本与依赖

首轮以 librime 1.17.0 为候选固定版本，依赖版本必须写入仓库配置并通过 CI 缓存。最终是否采用该版本，以 Android NDK 构建和真机验证结果为准；如果出现明确的 Android 兼容问题，只允许在任务记录中说明原因后调整到相邻稳定版本。

librime 的依赖至少包括其当前构建所需的 leveldb、marisa-trie、opencc、yaml-cpp 和静态 spdlog；Boost 是否需要由 Android CMake 检测结果决定。不要直接下载来源不明的预编译 `.so`，也不要把第三方构建产物当作源码依赖提交。

优先支持 `arm64-v8a` 和 `x86_64`。`x86_64` 用于 Android 16 模拟器自动化测试，不能因为真机只需要 arm64 就删除。

### WP5：预编辑、候选栏和按键路由

任务：

- 中文字母键转换为 Rime key event；
- 维护预编辑文本、光标、候选、选中项和页码；
- 编辑框继续通过 `setComposingText` 维护 Rime composing 语义，提交后正确清理状态；
- 用户已确定：编码区与候选栏分开。编码采用独立悬浮显示，从键盘物理左上方开始，不放进候选栏、不参与键盘测量、不增加键盘或输入法 inset，也不移动应用窗口；
- 悬浮编码采用输入法附属窗口，不申请系统悬浮窗权限，不抢焦点或拦截触摸；编码清空、语言/编辑框切换、键盘隐藏及服务销毁后及时消失；长编码单行限宽显示，不扩展布局；
- 候选栏放在字母键区上方并预留固定高度，只显示候选词与最右侧展开/收回按钮；适配标准 / 抬高模式和系统 insets，编码变化不能压缩候选栏或字母键；
- 支持候选点击；
- 支持空格选择当前候选；无组合输入时空格仍提交普通空格；
- 支持删除：有组合输入时删除拼音，没有组合输入时调用现有编辑删除；
- 用户已确定：候选栏采用单行横向滑动浏览，不设置点击翻页按钮；点击候选仍执行选词；
- 候选栏最右侧固定一个展开／收回按钮，不随候选横向滚动；按钮采用开口较宽、圆端点的折线图标，替代尖角字体字符，并保留无障碍展开状态；
- 用户已确认展开页采用左侧拼音/音节栏、右侧对应候选：左栏含“全部”及 Rime 实际候选首音节。普通键盘符号（!@#）键与回车键尺寸一致，候选页左侧拼音区域宽度等于符号键，右侧四个功能键的实际宽度等于普通回车键，两侧使用共用尺寸规则，不能只对齐容器而缩窄按钮。
- 单字模式采用五个等宽单字列，完整一行五个单字；全部模式的词语改为按实际文字宽度加少量统一边距紧凑换行，撤回二至五字词占用整列的规则。单字以约五分之一候选区为最小宽度，长短词依照原始候选顺序混排，超长词限于候选区宽度，不改成固定页面。选音节只筛选，不提交或改写悬浮编码；候选上屏使用原始全局索引，缺失读音保留在“全部”，滚动时继续加载后续拼音和候选；
- 点击按钮后，候选页从候选栏下缘向下展开，采用抽屉动画；再次点击反向收回。展开时顶部候选栏开始横向拖动，也应沿同一抽屉动画收回，顶部候选栏继续横滑，正在退出的候选页保持原内容，动画结束后才恢复普通键盘。候选页内部纵滑、音节栏滚动和图标滚屏不收回；再次展开采用横滑后的接续起点。采用绑定修订的单向收回动作，重复手势不重新展开，迟到手势不影响新输入。支持动画中快速反向操作，不重叠、不穿透点击；
- 用户已确定：抽屉向下展开后占满整个键盘内容区域，包括原字母区和底部七键区域，形成完整候选页。普通字母键与七键底栏均不保留显示或交互；候选栏右侧保留收回入口，收回后恢复普通键盘。底部七键要求适用于普通键盘，不限制候选页布局；不额外把保持总高度写成用户要求。展开页采用多行候选、纵向滚动，系统导航与抬高安全区域仍由系统管理；
- 横向候选栏与展开页共享候选数据和原始索引，并接续显示：展开页从候选栏当前最后完整可见候选的下一原始编号开始，不再重复前缀；右边半露出的候选保留在展开页起点，无完整可见项时从相交项开始。以实际布局而非裁剪后的触控区域计算，不按文字去重；横滑候选栏同步更新起点，起点未变的收回/重开保留纵向位置。追加加载保持编号与锚点，新输入修订重新计算；筛选作用于接续后的候选。滑动接近末尾时按需加载更多，顶部候选栏仍横滑浏览。展开页始终保留连续手动纵向滑动，不得切成固定九项或其他固定数量的页面。右侧上/下图标只让同一候选网格从当前位置滚动约一屏，不向 Rime 发送翻页按键、不改变编码或高亮；无障碍保留操作说明，按钮视觉使用图标；
- 展开页左下固定“全部／单字”二态切换，不含“词语”；右栏自上而下为删除、向上滚动、向下滚动、候选提交图标，右上角收回入口保留。手动拖动与按钮滚动可交替操作，不允许按钮模式替代原有滑动。
- 加载更多不能改变空格选词目标；候选绑定组合版本与全局索引，避免跨页选错、重复加载和过期响应覆盖新候选；
- 同一组合展开／收回保留各自滚动位置；拼音变化或部分选词后重置候选滚动位置；组合结束、切换语言／编辑框时收回抽屉并清理旧候选；
- 滑动手势不能误触选词，抽屉内容不能把触摸传给下方字母键。动画尊重系统动画设置，标准／抬高及尺寸变化时均不侵入系统底栏；
- 支持回车：有组合输入时提交原始拼音并结束组合，本次不执行编辑器动作；无组合输入时沿用阶段二搜索、完成、发送或换行逻辑；
- 中英文标点行为必须统一测试。推荐目标是中文组合存在时先提交当前候选，再插入对应中文标点；实际按键处理以 Rime 行为和验收结果为准；
- 候选列表为空、引擎异常和部署未完成时，界面仍可使用英文键盘。

完成条件：输入 `nihao` 能看到预编辑和候选；选择后编辑框得到汉字；连续输入、删除、空格、标点和回车不会重复或丢字。

## 六、输入行为规范

### 6.1 中文基本流程

```text
切换中文 → 输入 n i h a o
→ Rime 产生 preedit "nihao"
→ 候选栏展示候选
→ 点击候选或按空格
→ commitText("你好") 直接替换 composing 区域
→ 如有剩余预编辑则继续显示，否则清空候选状态
```

### 6.2 组合态下的按键

| 按键 | 有预编辑 | 无预编辑 |
|---|---|---|
| 字母 | 送入 Rime | 送入 Rime，开始预编辑 |
| 删除 | 删除拼音或由 Rime 处理 | 删除编辑框前一个完整字符 |
| 空格 | 选择当前候选 | 提交普通空格 |
| 候选点击 | 提交选中候选 | 无操作或保持候选栏隐藏 |
| 候选栏横向滑动 | 浏览候选，接近末尾按需加载 | 不显示旧候选 |
| 最右侧展开／收回按钮 | 向下展开候选抽屉或反向收回 | 隐藏或禁用 |
| 展开页纵向滑动 | 浏览更多候选，接近末尾按需加载 | 无操作 |
| 回车 | 提交原始拼音，本次不执行编辑器动作 | 执行编辑器动作 |
| 逗号 / 句号 | 按确定的 Rime 标点策略处理 | 提交中文模式标点 |
| 小地球短按 | 清理组合后切换语言 | 切换语言 |
| 小地球长按 | 打开系统输入法选择入口 | 打开系统输入法选择入口 |

### 6.3 安全规则

- 密码输入框不启动中文 Rime session；
- 密码文本不进入 Rime 用户学习；
- 不记录拼音、候选、提交文本和编辑框内容；
- 不读取剪贴板，除非用户主动点击现有粘贴操作；
- APK 不新增网络权限；
- Rime 用户目录只保存在应用私有目录；
- JNI 和日志中的错误信息只能包含错误码、阶段和版本信息。

## 九、风险和处理顺序

### 原生库无法在 Android 构建

先保留 WP1 独立构建探针，禁止在 UI 代码中夹带未验证的 native 依赖。优先解决 NDK、CMake、依赖和 ABI，再进入 JNI。

### 首次部署阻塞键盘

部署放到 worker。键盘先显示英文；中文按钮显示准备状态，部署完成后自动启用中文模式。

### Rime 输出和 InputConnection 重复

所有输出通过统一 `RimeOutput` 归并器处理，先验证 input session 和请求序号，再由 `commitText` 直接替换当前 composing 区域；禁止先 `finishComposingText` 保留拼音再追加汉字。一次提交后若引擎仍有剩余预编辑，再设置新的 composing 文本。取消时只在连接和 composing 范围仍有效时删除自有预编辑；连接已失效则仅清理引擎，不向新编辑框补写。

### 交互规则补充（优先于前文概述）

- 有预编辑时按回车：提交原始拼音并结束组合，本次不发送、不搜索、不换行；下一次无预编辑的回车才执行编辑器动作，避免误发送。
- 小地球短按：在当前有效连接中提交原始拼音后切换语言；不自动猜选汉字。
- 中文 Shift：保留既有单次大写和锁定语义。产生大写字符前提交原始拼音，再直接输入大写字符；中文拼音路径不应用英文自动句首大写。
- 用户点击编辑框移动光标或进入编辑面板：结束当前组合，不自动选词；区分自己设置 composing 触发的选区回调和外部光标移动，避免每次输入都清空候选。
- 切换编辑框：立即失效旧会话，清理引擎与候选，不向新连接补交旧文本；不保证已经失效的旧连接能删除预编辑，禁止盲删。
- 候选索引明确区分页内与全局；点击携带候选快照编号，过期点击丢弃。部分选词后可能还有剩余拼音，不能假定一次选择必定结束组合。
- Rime 的 UTF-8 字节偏移必须转换为 Android/Kotlin 的 UTF-16 索引，覆盖扩展汉字和 emoji；读取后释放 C API 上下文与提交对象。
- 原生崩溃无法由普通 JNI 异常捕获保证恢复；部署失败可回退英文，native 内存安全依靠生命周期检查和测试。启动时用 `rime_get_api()` 获取公开 API，避免依赖私有 C++ ABI。
- 部署完成只开放中文入口，不强行改变用户正在使用的英文模式。维护线程结束前不得并发访问会话。
- 尊重 `IME_FLAG_NO_PERSONALIZED_LEARNING`：禁用学习；若方案不能可靠保证，走不学习的直输路径。用户学习数据库不纳入默认云备份。
- 版本依赖以所选 tag/commit 的实际源码为准；当前 master 的依赖（包括 spdlog）不能直接当作 1.17.0 的依赖清单。
- 16 KB 验证同时检查所有 ELF LOAD 段和 APK ZIP 对齐；静态检查不等于已在 16 KB 内核运行，报告中分开记录。
- 许可证交付除了 NOTICE，还须按各许可证提供相应源码、修改记录和其他要求；已查得 luna-pinyin 数据仓库使用 LGPL-3.0 文本。
- 资源包校验哈希，在临时目录完整部署后切换成功版本；停用数据库后再备份，部署失败保留旧可用数据。首次无可用资源时提供重试和英文入口。

### Android 16 或 16 KB 页兼容问题

把 ELF 对齐检查放入 Actions；禁止等到用户拿 APK 安装后才发现 native 库不兼容。必要时先用 x86_64 模拟器和 arm64 真机分别验证。

### 方案或词库许可证不清楚

只使用能够在仓库中随包提供许可证文件的方案和词库；在 `NOTICE` 或 `docs/licenses/` 中记录 librime、方案、词典和第三方依赖的来源与许可证。

### Rime 用户数据升级损坏

共享资源和用户目录分开。部署失败时保留旧资源和用户目录，写入新版本标记必须在部署成功后执行。用户目录升级前先做原子备份或至少保留上一个部署状态。
